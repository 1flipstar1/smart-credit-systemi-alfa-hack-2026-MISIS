# Обязательная дизайн-система проекта

Все интерфейсы этого проекта создаются на официальной Alfa Core Components.
Источник: https://core-ds.github.io/core-components/master/?path=/docs/intro--docs

Перед любой работой над UI:
1. Прочитать `docs/core-components/README.md` и `docs/core-components/COMPONENTS.md`.
2. Найти подходящий готовый компонент. Перед использованием прочитать его локальный API в `docs/core-components/api/` и фактические `.d.ts` установленного пакета. Проверять также наследуемые типы и defaults реализации; не придумывать props.
3. Использовать настоящие React-компоненты `@alfalab/core-components`, официальные темы и токены. Не рисовать аналоги Button, Input, Select, Radio, Tag и других доступных контролов вручную. CSS проекта отвечает за композицию и адаптивную сетку; внутренние классы библиотеки не переопределять.
4. Для нового элемента, который не удаётся найти, сначала проверить полный каталог и официальный Storybook. Только при отсутствии подходящего элемента создавать композицию из существующих компонентов.
5. После изменений запускать `npm run check`, `npm run build`, `npm run verify`. Обновлять превью галереи при визуальных изменениях.

Приложение: `src/app.tsx`, стили композиции: `src/layout.css`. Пять HTML и галерея в `output/bank-ui-study` генерируются через `npm run build` и открываются напрямую. Не редактировать их вручную и не запускать старый `build_study.py`: он сохранён только как исторический материал.

Весь пакет установлен, но в браузер включаются только используемые компоненты. Официальная тема — `site.css`. Для красного CTA нужен `view="accent"`; числовые размеры проверять по API. Версии фиксируются package-lock.json. После явного обновления зависимостей запускать `npm run ds:catalog`, проверять breaking changes и пересобирать наброски. Storybook master может отличаться от закреплённой версии; для API приоритет у установленной версии.

Эти инструкции действуют во всех следующих сессиях, которые открывают этот проект и читают AGENTS.md. Нельзя обещать, что вся библиотека навсегда находится в памяти модели: проверять справочник при каждой задаче.
