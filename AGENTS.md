# Правила работы над проектом

## Техническое задание и границы задач

ТЗ проекта находится в [Альфа_Хак_Умный_кредитный_кабинет.pdf](Альфа_Хак_Умный_кредитный_кабинет.pdf).

Перед началом каждой задачи прочитать ТЗ и проверить, соответствует ли ему запрошенная работа. Если задача выходит за рамки ТЗ, является лишней для его выполнения или противоречит его требованиям, не выполнять её и сообщить пользователю причину со ссылкой на соответствующие положения ТЗ. Если задача соответствует ТЗ, выполнять её с соблюдением всех применимых требований ТЗ и правил ниже.

## Обязательная дизайн-система проекта

Все интерфейсы этого проекта создаются на официальной Alfa Core Components.
Источник: https://core-ds.github.io/core-components/master/?path=/docs/intro--docs

Перед любой работой над UI:
1. Изучить подходящие прототипы и материалы фирменного дизайна банка в папке [Библиотека ui](<Библиотека ui/>). Всегда сверяться с ними при работе над фронтендом: при выборе композиции, визуальной иерархии, типографики, цветов и поведения интерфейса, а также при проверке результата. Использовать их как визуальные ориентиры совместно с ТЗ и официальной Alfa Core Components; требования к настоящим компонентам, темам и токенам сохраняются.
2. Прочитать `docs/core-components/README.md` и `docs/core-components/COMPONENTS.md`.
3. Найти подходящий готовый компонент. Перед использованием прочитать его локальный API в `docs/core-components/api/` и фактические `.d.ts` установленного пакета. Проверять также наследуемые типы и defaults реализации; не придумывать props.
4. Использовать настоящие React-компоненты `@alfalab/core-components`, официальные темы и токены. Не рисовать аналоги Button, Input, Select, Radio, Tag и других доступных контролов вручную. CSS проекта отвечает за композицию и адаптивную сетку; внутренние классы библиотеки не переопределять.
5. Для нового элемента, который не удаётся найти, сначала проверить полный каталог и официальный Storybook. Только при отсутствии подходящего элемента создавать композицию из существующих компонентов.
6. После изменений запускать `npm run check`, `npm run build`, `npm run verify`. Обновлять превью галереи при визуальных изменениях.

Приложение: `src/app.tsx`, стили композиции: `src/layout.css`. Пять HTML и галерея в `output/bank-ui-study` генерируются через `npm run build` и открываются напрямую. Не редактировать их вручную и не запускать старый `build_study.py`: он сохранён только как исторический материал.

Весь пакет установлен, но в браузер включаются только используемые компоненты. Официальная тема — `site.css`. Для красного CTA нужен `view="accent"`; числовые размеры проверять по API. Версии фиксируются package-lock.json. После явного обновления зависимостей запускать `npm run ds:catalog`, проверять breaking changes и пересобирать наброски. Storybook master может отличаться от закреплённой версии; для API приоритет у установленной версии.

Эти инструкции действуют во всех следующих сессиях, которые открывают этот проект и читают `AGENTS.md` или `CLAUDE.md`. Поддерживать оба файла полностью идентичными: при изменении правил в `AGENTS.md` копировать весь обновлённый текст в `CLAUDE.md`. Нельзя обещать, что ТЗ и вся библиотека навсегда находятся в памяти модели: читать ТЗ перед каждой задачей, а при работе над фронтендом проверять справочник и материалы в `Библиотека ui/`.
